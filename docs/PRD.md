# AI 论文阅读助手：产品需求文档

- 版本：0.1
- 日期：2026-10-04
- 产品形态：个人本地部署的 Web 应用
- 目标用户：需要阅读英文科研论文的研究人员和学生

## 3. 产品目标

### 3.1 目标

- 在一个页面完成“找论文、打开论文、理解论文、追问论文”。
- 让翻译和回答结果可缓存，降低重复调用成本。
- 支持用户自带模型服务，包括 OpenAI 兼容接口和本地模型服务，不同任务支持不同的模型配置。

## 4. 用户流程

### 4.1 导入论文

1. 用户上传本地 PDF，或粘贴 arXiv `abs`/`pdf` 链接。
2. 系统识别 arXiv 标识，获取标题、作者、摘要和版本信息；链接论文下载后保存在本地库。

### 4.2 阅读与提问

1. 左栏选择文件夹和论文。
2. 中栏显示 PDF 原文，支持页码、缩放、搜索和选区。
3. 选中文本后点击“翻译/解释/加入聊天”。
4. 在页面上框选图表或图片后拖入右栏聊天框。
5. 翻译任务不计入上下文，避免上下文混乱，仅作为side chat任务

## 5. 页面与功能需求

### 5.1 三栏工作区

**左栏：论文目录**

- 文件夹创建、重命名、删除、嵌套和拖动排序。
- 论文导入、移动、删除、收藏和最近阅读。
- 论文标题、作者、年份搜索。

**中栏：正文阅读器**

- PDF.js 或同等方案渲染原始 PDF。
- 页码跳转、缩放、连续/单页阅读、文本搜索。
- 文本选区发送到 Agent。
- 框选页面区域，生成裁剪图片并发送到 Agent。

**右栏：AI Agent**

- 流式聊天、会话历史、停止生成、重新生成和复制。
- 当前论文、当前页、选中文本、图片作为上下文卡片显示。
- 快捷操作：翻译选区、概括全文、概括当前章节、精读当前章节、解释图片/表格。
- 支持切换“当前论文”和“多篇论文”上下文范围。

### 5.2 论文库与数据

每篇论文至少保存：

- 标题、作者、摘要、年份、来源链接、arXiv 标识和版本。
- 所属文件夹、标签、收藏状态。

首版建议使用 SQLite 保存元数据，使用本地文件夹保存 PDF 和图片资源。目录结构示例：

```text
library/
  papers/<paper-id>/original.pdf
  cache/translations/<paper-id>.json
```

## 6. AI 任务需求

### 6.1 任务与模型路由

设置中允许配置多个模型服务和模型预设：

| 任务 | 默认模型倾向 | 输入 |
|---|---|---|
| 选区翻译 | 低成本、低延迟 | 选中文本、术语表、目标语言 |
| 全文/章节概括 | 高质量文本模型 | 当前页文本、选中文本和论文上下文 |
| 精读问答 | 高质量模型 | 当前页文本、选中文本、图片和用户问题 |
| 图片/表格解释 | 支持视觉的模型 | 裁剪图或用户上传图片 + 当前页文本 |

模型服务配置保存在本机配置文件或系统密钥存储中，并与前端源码、Git 仓库隔离。

### 6.3 回答上下文与引用

1. 将当前页文本、用户选区、当前页码和图片作为 Agent 上下文。
2. 快捷任务通过 Pi prompt template 注入对应任务提示词。
3. 回答携带 `paper_id` 和当前页码。
4. 用户点击页码后，中栏跳转到对应页面。

## 7. 翻译缓存

缓存键包含以下字段：

```text
source_text
source_language
target_language
```

要求：

- 命中后直接返回缓存结果。
- 原文块变化时自动失效。
- 支持单块缓存和批量预翻译。
- 仅将成功翻译结果写入缓存。
- 展示缓存命中状态和删除缓存入口。

## 8. 非功能需求

- 本地启动后通过浏览器访问，默认只监听本机地址。
- 论文库和翻译缓存支持导出与备份，恢复后保持目录、缓存和会话关系一致。
- 大文件和模型任务使用异步队列，保持页面交互流畅。
- 模型调用显示任务状态、耗时和错误原因；支持超时、重试和取消。

## 9. MVP 验收标准

1. 能创建至少两级文件夹，并把本地 PDF 和 arXiv 链接论文放入指定文件夹。
2. 重启应用后论文、文件夹、PDF 和阅读位置仍存在。
3. 页面稳定显示三栏；三栏宽度可调整。
4. PDF 文本选区可发送到聊天框并完成翻译；同一块内容第二次翻译命中缓存。
5. 用户可框选 PDF 页面区域，图片随问题发送给视觉模型，并能在聊天消息中看到页码来源。
6. 能请求全文概括、当前章节精读和图片解释；回答至少包含可点击的页码或结构块引用。
7. 可分别配置翻译模型、分析模型和视觉模型，并能测试连接。
8. API 密钥、原始 PDF 和个人聊天数据存储在本机后端及数据目录，与前端构建产物和 Git 仓库隔离。

## 10. 开发优先级

### P0：可用闭环

- 本地服务启动、SQLite、论文/文件夹管理。
- PDF.js 阅读器和三栏布局。
- 本地 PDF/arXiv 导入。
- 选区翻译、章节概括、基础论文问答。
- 模型预设和翻译缓存。

### P1：核心差异化体验

- 页面区域框选和图片截图聊天。
- 图表/表格视觉解释。
- 全文搜索、会话持久化。

## 11. 推荐技术边界

- 前端：React + TypeScript；PDF 使用 PDF.js；三栏尺寸使用可调整面板组件。
- 本地后端：Node.js 服务，负责文件系统、SQLite 和模型代理。
- 模型：统一适配 OpenAI 兼容接口，同时允许不同任务绑定不同模型。
- 实时输出：服务端事件流（Server-Sent Events，SSE）或 WebSocket。
- 数据访问：所有模型 API 密钥只由本地后端持有。

技术选型可以在实现前调整，但原始 PDF、图片资源、引用定位和缓存键保持独立建模。
